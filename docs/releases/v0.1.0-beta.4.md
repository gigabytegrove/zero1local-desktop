# Zero1Local Desktop v0.1.0-beta.4 — Administrator sign-in and NAS workspace

**Source provenance:** use the tag's exact commit SHA. This beta must be built, regression-tested, checksummed, and published from dockeradm before it is installable.

## Improvements
- New NAS enrollment now requires administrator username/password and optional TOTP; only a successful official Zero1Local login saves the appliance.
- Supports reconnecting and signing out per NAS, with credential isolation. Passwords and session cookies are not saved to disk.
- HTTPS certificate validation and explicit cleartext HTTP warning/acknowledgement.
- First-party authenticated management navigation: system, storage, network, Docker, hardware, users/groups, services, tasks, backups, protection and notifications.
- Unified SMB/NFS share inventory avoids rendering a dual-protocol backing folder twice, with protocol-specific mapping controls.
- Top-level File Manager with NAS share-rooted browsing, folder creation, upload, download, rename and Move to Recycle Bin. The NAS continues to enforce permissions.
- Updated local CSRF protection, request limits, bounded JSON, transfer restrictions and integration/regression tests.

## Boundaries and limitations
- File transfer is capped at 256 MiB per request; large files and complete advanced management remain available in the original Zero1Local browser UI.
- Desktop authentication sessions are intentionally ephemeral. SMB/NFS mapping uses the OS's own identity and credentials.
- No direct administrator credentials are persisted. The app does not alter NAS account permissions or turn off MFA.
- Beta only. Windows/Linux native desktop UI, authentication with a real appliance, mount verification, and end-to-end updater behavior still require target-host acceptance. No macOS package is included.
