# Zero1Local Desktop v0.1.0-beta.7 — Native updates that actually work

The desktop update flow is rebuilt around two explicit actions: **Check for updates** and **Install update**.

### Fixed
- Debian-packaged Linux copies can check GitHub Releases without a disabled button.
- The Linux updater no longer downloads a `.deb` into `~/Downloads` and asks the user to install it manually.
- Clear latest-version and last-check results, including errors if GitHub cannot be reached.
- Status, progress phase and a visible restart button when installation completes.

### Linux Debian installation
- Downloads the exact newer `amd64` release in a private mode-0700 staging directory.
- Validates GitHub asset size and `SHA256SUMS` before installing.
- Verifies the package name, architecture and source-derived Debian version.
- Uses a normal PolicyKit administrator authorization prompt and APT to upgrade the installed package, with package removals disallowed.
- Confirms dpkg's installed version and offers **Restart Desktop now**. The companion never asks for or stores a root password.

### Windows and portable Linux
- Checking and installing are distinct. Wails handles the checksum-verified portable updater archive when the user chooses Install.

### Migration
**Beta 6 or earlier Debian installations need one final traditional installation of Beta 7** because their already-released executable cannot invoke the new updater. Updates *after* Beta 7 are managed inside Desktop Settings.

### Quality and boundaries
No changes to Zero1Local NAS firmware or server. Beta only. Native graphical PolicyKit, APT, restart and Windows portable updater acceptance on the target operating systems remain unverified until exercised there.
